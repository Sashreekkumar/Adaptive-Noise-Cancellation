# ONNX Audio Cleaner — Model & Script Reference

This folder is a **standalone, ONNX Runtime–only** pipeline for cleaning noisy
speech recordings with DeepFilterNet3, then writing the result out as an mp3.
It's a sibling of a PyTorch-based `audio_cleaner` package — same pipeline
shape, same stage names, but every stage here is implemented with `numpy` +
`onnxruntime` so it has **no dependency on torch or the `df` package at
inference time**. Torch/`df` are only needed once, offline, to export the
`.onnx` graph (`export_to_onnx.py`).

```
project/
├── run_onnx.py              # entry point you actually run
└── onnx/                    # the package documented below
    ├── __init__.py
    ├── cli.py
    ├── config.py
    ├── export_to_onnx.py
    ├── model.py
    ├── loader.py
    ├── preprocessing.py
    ├── enhancement.py
    ├── postprocessing.py
    ├── exporter.py
    ├── pipeline.py
    └── vendor/
        └── torch_df_streaming.py
```

## One-time setup: exporting the model

Before you can clean any audio, you need a `.onnx` graph + its `.meta.json`
sidecar. That's a **one-time, offline** step done with `export_to_onnx.py`,
and it's the only part of this project that touches PyTorch or the `df`
package.

### `vendor/torch_df_streaming.py`
Vendored, unmodified copy of `grazder/DeepFilterNet`'s
`torch_df_streaming.py`. Contains:
- **`ExportableStreamingTorchDF`** — a pure-PyTorch reimplementation of
  DeepFilterNet3's STFT / ERB-feature / deep-filtering DSP (normally done in
  a compiled Rust extension that `torch.onnx.export` can't trace), written
  specifically so it *can* be traced. It processes exactly one 480-sample
  (10 ms) frame at a time and threads all recurrent/normalization state
  through as an explicit `states` tensor (an ONNX graph has no memory of its
  own).
- **`TorchDFPipeline`** — loads the official DeepFilterNet3 checkpoint into
  that module and loops it over a whole file in pure PyTorch (no ONNX
  involved). Also runnable directly as a script for a torch-only sanity
  check:
  ```bash
  python -m onnx.vendor.torch_df_streaming \
      --audio-path noisy.wav --output-path clean_torch.wav \
      [--device cpu|cuda] [--always-apply-all-stages]
  ```
Do not edit this file — it's kept as a clean, diffable copy of upstream.

### `export_to_onnx.py`
Builds the `TorchDFPipeline` above, traces `ExportableStreamingTorchDF` with
`torch.onnx.export`, and writes:
- `<output>.onnx` — the streaming graph (inputs: `input_frame`, `states`,
  `atten_lim_db`; outputs: `enhanced_frame`, `new_states`, `lsnr`)
- `<output>.meta.json` — sidecar with `frame_size`, `fft_size`,
  `states_full_len`, `sample_rate`, read back by `model.py`

It also self-validates the export by comparing PyTorch vs. ONNX output on a
silent frame and on 5 random frames with state carried forward, printing the
max absolute difference for each.

```bash
python -m onnx.export_to_onnx \
    -o deepfilternet3.onnx \
    [--model_base_dir DeepFilterNet3] \
    [--opset 17]
```
Requires (export-time only): `torch`, `torchaudio`, `onnx`, `onnxruntime`,
`df` (deep-filter), plus a DeepFilterNet3 checkpoint discoverable the way
`df.enhance.init_df()` normally finds one.

## Runtime pipeline (ONNX Runtime only, no torch)

### `run_onnx.py`
The script you actually invoke. Lives as a **sibling** of the `onnx/`
package (not inside it). Just imports and calls `onnx.cli.main()`.

### `onnx/cli.py`
Argument parsing and the single-file / batch-folder driver.

```bash
# single file
python run_onnx.py input.mp3 -o clean.mp3 --onnx_path deepfilternet3.onnx

# batch folder (recurses over *.mp3/*.wav/*.m4a/*.flac/*.ogg)
python run_onnx.py ./noisy_dir -o ./clean_dir --onnx_path deepfilternet3.onnx
```

Full flags:

| Flag | Default | Meaning |
|---|---|---|
| `input` (positional) | — | noisy input file **or** a folder for batch mode |
| `-o, --output` | file: `<input>_clean_onnx.mp3`; folder: `<input>_clean_onnx/` | output mp3 or output folder |
| `--onnx_path` | *required* | path to the exported `.onnx` (its `.meta.json` must sit alongside it) |
| `--atten_lim_db` | `None` | caps DeepFilterNet3 attenuation in dB; lower = less over-suppression |
| `--blend_wet` | `1.0` | dry/wet blend, e.g. `0.9` = 90% enhanced + 10% pre-enhancement audio |
| `--normalize_volume` | off | apply final RMS loudness normalization |
| `--target_dbfs` | `-26.0` | RMS normalization target |
| `--hpf_cutoff` | `70` Hz | pre-enhancement high-pass cutoff |
| `--band_low` / `--band_high` | `80` / `8000` Hz | post-enhancement band-pass edges |

In batch mode the model is loaded once and reused for every file, progress is
shown with `tqdm`, per-file failures are caught and reported without
aborting the run, and a summary of average/min/max latency and real-time
factor (RTF) is printed at the end.

### `onnx/config.py`
Central place for every tunable default (`MODEL_SR=48000`, `HPF_CUTOFF_HZ=70`,
`TARGET_DBFS=-26.0`, `BAND_LOW_HZ=80`, `BAND_HIGH_HZ=8000`, `MP3_BITRATE=
"192k"`). Duplicated verbatim from the torch `audio_cleaner` package so this
folder has zero import dependency on it.

### `onnx/model.py`
Loads the exported ONNX graph **once per process** and caches it by resolved
path in `_MODEL_CACHE`.
- `get_model(onnx_path, providers=None)` — returns a cached `OnnxModel`,
  loading it on first call.
- `OnnxModel` — wraps an `onnxruntime.InferenceSession`; reads `frame_size`,
  `fft_size`, `states_full_len`, `sample_rate` from the `.meta.json` sidecar;
  `run_frame(frame, states, atten_lim_db)` runs one 480-sample frame through
  the graph and returns `(enhanced_frame, new_states)`.
- Raises `FileNotFoundError` with a clear message if the `.meta.json`
  sidecar is missing (i.e. `export_to_onnx.py` wasn't run first).

### `onnx/loader.py`
`load_audio(path, sr=config.MODEL_SR)` — decodes any ffmpeg-readable file to
mono float32 PCM at the target sample rate via a single `ffmpeg` subprocess
call (piping raw PCM back on stdout), instead of `librosa`/`audioread`'s
slower shell-out-per-frame approach.

### `onnx/preprocessing.py`
Stage 1, applied **before** the model sees the audio:
- `remove_dc_offset(audio)`
- `highpass(audio, sr, cutoff_hz)` — 4th-order Butterworth, zero-phase
  (`sosfiltfilt`)
- `rms_normalize(audio, target_dbfs)` — RMS loudness normalization with
  peak-safety clamp at 0.99
- `preprocess(...)` — runs the three in order, each individually skippable

### `onnx/enhancement.py`
Stage 2, the actual denoising:
- `enhance_audio(audio, model, atten_lim_db=None)` — pads the input to a hop
  multiple (plus `fft_size` for the synthesis tail), zero-initializes the
  `states` tensor, then loops `model.run_frame(...)` 480 samples at a time in
  numpy (the numpy equivalent of `TorchDFPipeline.forward()`'s chunking
  loop), concatenates, trims the synthesis-delay offset, and truncates back
  to the exact input length.

### `onnx/postprocessing.py`
Stage 3, applied **after** the model:
- `bandlimit(audio, sr, low_hz, high_hz)` — 4th-order Butterworth band-pass,
  zero-phase
- `postprocess(...)` — optional dry/wet blend with the pre-enhancement
  audio, band-limit to the speech range, optional final RMS normalization,
  then a peak-safety clamp

### `onnx/exporter.py`
`export_mp3(audio, sr, out_path, bitrate=config.MP3_BITRATE)` — pipes raw
float32 PCM directly into `ffmpeg`'s stdin and lets it write the mp3 straight
to disk (no intermediate `.wav`).

### `onnx/pipeline.py`
Glues every stage above into one call and times each stage.
- `clean_audio_file(input_path, output_path, *, onnx_path, atten_lim_db=None, blend_wet=1.0, normalize_volume=False, target_dbfs=..., hpf_cutoff=..., band_low=..., band_high=..., skip_dc=False, skip_hpf=False, skip_pre_norm=False) -> CleanResult`
- `CleanResult` (dataclass): `output_path`, `latency_seconds` (excludes
  one-time model load), `audio_duration_seconds`, `rtf` (latency ÷ duration;
  <1 = faster than real time), `stage_seconds` (dict: `load`, `preprocess`,
  `enhance`, `postprocess`, `export`)

### `onnx/__init__.py`
Just re-exports `clean_audio_file` as the package's public API:
```python
from onnx import clean_audio_file
```

## How to use it

### 1. Install dependencies
See `requirements.txt` / `pyproject.toml` below. You'll need `ffmpeg` on
your `PATH` as well (used via `subprocess`, not a Python binding).

### 2. Export the model once
```bash
pip install torch torchaudio onnx onnxruntime deepfilternet
python -m onnx.export_to_onnx -o deepfilternet3.onnx --model_base_dir DeepFilterNet3
```
This produces `deepfilternet3.onnx` and `deepfilternet3.meta.json` in the
current directory — keep them next to each other.

### 3. Clean audio (torch no longer needed)
```bash
# one file
python run_onnx.py noisy.mp3 -o clean.mp3 --onnx_path deepfilternet3.onnx

# a whole folder, with a gentler attenuation limit and final loudness normalization
python run_onnx.py ./recordings -o ./recordings_clean \
    --onnx_path deepfilternet3.onnx \
    --atten_lim_db 20 \
    --normalize_volume
```

### 4. Or call it from Python
```python
from onnx.pipeline import clean_audio_file

result = clean_audio_file(
    "noisy.mp3", "clean.mp3",
    onnx_path="deepfilternet3.onnx",
    atten_lim_db=20,
    normalize_volume=True,
)
print(result.rtf, result.stage_seconds)
```

Note: only the *export* step needs `torch`/`torchaudio`/`onnx`/`df`. Once you
have the `.onnx` + `.meta.json` files, the runtime path (`run_onnx.py`,
everything under `onnx/` except `export_to_onnx.py` and `onnx/vendor/`) only
needs `onnxruntime`, `numpy`, `scipy`, `tqdm`, and a system `ffmpeg`.
